# paper-agent

一个**零框架依赖**的 Agent 运行时。

手写的五步循环、工具注册器、三道护栏、以及一套完整的失败处理。
这是 16 周学习计划的主线项目，每周往里加东西 —— 目标不是"跑个 demo"，
而是"每一行都能解释清楚"。

---

## 快速开始

```bash
# 1. 建虚拟环境
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux

# 2. 装依赖
pip install openai python-dotenv pydantic httpx2

# 3. 配密钥（复制模板，填自己的）
copy .env.example .env
# 编辑 .env，填入 ARK_API_KEY

# 4. 冒烟测试
python hello_llm.py
```

看到一段回答 + token 统计，说明环境通了。

## 核心设计

### 五步循环

```
① 调模型  → ② 看要不要工具 → ③ 解析意图 → ④ 执行工具 → ⑤ 回填 → 回到 ①
```

**只有第 ④ 步真正做事**，其余四步都是搬运和判断。
所以 loop 写得好不好，主要看搬运和判断是否可靠。

### 分层

| 层 | 管什么 | 不知道什么 |
|---|---|---|
| `loop.py` | 什么时候执行、执行完干什么 | 有哪些具体工具 |
| `tools.py` | 单个工具怎么执行、参数怎么校验 | 有循环这回事 |
| `tools_impl.py` | 业务逻辑（检索文档） | 谁来调、什么时候调 |

**验证方式：加一个新工具，需要改几个文件？**
答案是 1 个（新建工具文件）—— 如果超过 1 个，说明分层破了。

### 三道护栏

| 护栏 | 防的病 | 没有它会怎样 |
|---|---|---|
| `max_steps` | 绕圈子 | 模型反复调工具，跑到天荒地老 |
| `token_budget` | 烧钱 | 每轮正常但总成本失控 |
| `max_seconds` | 卡死 | 工具挂起，无限等待 |

**三者防的故障不同，不能互相替代。**

## 失败模式清单

这张表是本项目的「运维手册」：出了问题时，按"现象"查到"系统会怎么做"和"用户看到什么"。

> 全部行为都有对应的验收脚本：`failure_drill.py`（9 项检查）

### A. 模型 / 服务商层

| 现象 | 在哪一步 | 分类 | 系统行为 | 用户看到 |
| --- | --- | --- | --- | --- |
| 网络超时 / 连接断 | ① 调模型 | `transient` | 退避重试（最多 3 次） | 略慢，多数情况无感 |
| 限流 429 | ① | `transient` | 退避重试；有 `Retry-After` 则优先听它 | 略慢 |
| 服务端 5xx | ① | `transient` | 退避重试 | 略慢 |
| 上下文超长 400 | ① | `permanent` | **不重试**，直接失败 | "任务失败：上下文过长" |
| 输出被截断（`length`） | ① | `length` | 停止本轮，不当作最终答案 | "回答不完整" |
| 内容被审核拦下 | ① | `content_filter` | 停止，**不算成功** | "内容无法生成" |
| 输出格式脏（代码块/解释/尾随逗号） | ③ 解析参数 | 本地兜底 | **本地宽松解析救回，不花 token** | 无感 |
| 输出 JSON 被截断 | ③ | `model_fixable` | 报 `invalid_json` + `truncated=true`，回填给模型 | 可能多一轮 |
| 完全不是 JSON（模型拒绝） | ③ | `model_fixable` | 报 `invalid_json`，回填让模型重来 | 可能多一轮 |
| 工具名编造 | ③ → ④ | `model_fixable` | 报 `unknown_tool` + 可用列表 | 可能多一轮 |
| 参数类型错 / 缺字段 | ③ → ④ | `model_fixable` | 报 `invalid_args` + 逐字段说明 | 可能多一轮 |

### B. 工具层

| 现象 | 在哪一步 | 分类 | 系统行为 | 用户看到 |
| --- | --- | --- | --- | --- |
| 工具内部超时 | ④ 执行工具 | `transient` | 退避重试 | 略慢 |
| 工具内部权限不足 | ④ | `permanent` | **只试 1 次**，回填让模型换路 | 模型换个说法或说做不到 |
| 工具内部代码 bug | ④ | `permanent` | 只试 1 次，记录 `tool_error` | 同上 |
| 工具返回空结果 | ④ | `ok: true` | **不算失败**，回填空列表 + 提示 | "没有找到相关资料" |
| 工具返回超大结果 | ④ | —— | 截断到上限，并标记 `truncated` | 可能信息不全 |
| 参数诱导路径穿越（`../.env`） | ④ | `model_fixable` | 白名单正则拦截 | "无法访问该文档" |

### C. 编排层（护栏）

| 现象 | 在哪一步 | 分类 | 系统行为 | 用户看到 |
| --- | --- | --- | --- | --- |
| 反复调工具、没进展 | 全循环 | `max_steps` | 跑满步数强制停止 | "任务未完成（步数上限）" |
| 总 token 失控 | 每轮开始前 | `budget` | 不再发起新请求 | "任务未完成（预算耗尽）" |
| 工具卡住 / 整体太慢 | 每轮开始前 | `timeout` | 不再发起新请求 | "任务超时" |
| 未预料的异常 | 任意 | `error` | 捕获，保留已完成步骤 | "任务失败，已执行 N 步" |

### D. 重复执行

| 现象 | 在哪一步 | 分类 | 系统行为 | 用户看到 |
| --- | --- | --- | --- | --- |
| 重试导致同一操作执行多次 | ④ | —— | **只对幂等操作开重试**；写操作需幂等键 | 若处理不当：重复扣款 |
| 用户重复提交同一请求 | 入口 | `replayed` | 幂等存储命中，直接返回上次结果 | 与首次一致 |

## 已知限制

诚实列出来，免得别人（或三个月后的自己）以为是 bug：

| 限制 | 影响 | 计划 |
| --- | --- | --- |
| 检索是朴素 2-gram，有假阳性 | 搜"问题"会命中任何文档 | W8 换 TF-IDF / 向量 |
| 幂等存储没有并发保护 | 两个相同 key 同时到达会都执行 | 后续加"进行中"状态 |
| 幂等存储是内存的 | 重启就失效 | 需要时换 Redis |
| 没有流式输出 | 用户要等完整回答 | W13 |
| 没有可观测性（trace / 指标） | 出问题只能看日志 | W10-W11 |
| 单进程，没有并发限流 | 高频调用会打爆下游 | W12 |
