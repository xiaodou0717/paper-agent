# 函数调用（Function Calling）

## 一句话定位

让模型"说出它想做什么"，由你的代码"决定做不做、怎么做"。
**模型永远不直接执行任何东西。**

## 三段式

```
① 你提供工具清单（name + description + parameters schema）
② 模型返回 tool_calls（要调哪个、参数是什么）
③ 你执行，把结果塞回 messages，再问一次
```

第 ③ 步是关键：**模型看不到你的执行过程，只看到结果。**
所以结果必须写清楚——成功是什么样、失败是什么原因。

## schema 设计：description 决定成败

模型选工具、填参数，**全靠 description**。

```
❌ "查询文档"
✅ "按关键词检索本地文档库，返回 doc_id 和标题列表。
    只做关键词匹配，不做语义检索。查不到时返回空列表而不是报错。"
```

第二版多了三个信息：做什么、怎么做、失败时什么样。
模型据此就能判断"该不该用这个工具"、"查不到是不是正常"。

## 并行调用

模型一次可以返回多个 tool_calls。这不是"模型变快了"，
而是**它判断这几个调用互不依赖**。

如果你的工具之间有依赖（A 的结果是 B 的输入），
要确保 schema 里说清楚——否则模型可能并行调，然后拿到错误的结果。

## 常见误区

**参数不做校验**

模型会给出：类型错的（`"3"` 而不是 `3`）、缺字段的、多字段的、
甚至完全编造的字段名。**每一层都要校验**，别信模型。

**工具返回一大坨原始数据**

模型看到的是文本。返回 5KB 的 JSON，它要花 token 去读，
而且很可能只看到开头。**该摘要就摘要，该截断就截断**（并说明截断了）。

**错误信息写"失败了"**

模型没法据此修正。要写"哪个参数不对、期望什么、你给的是什么"。
错误信息是给模型看的，不是给你自己看的。
