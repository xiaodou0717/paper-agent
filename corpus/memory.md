# Agent 的记忆机制

## 三种记忆

Agent 的记忆通常分三层，用途完全不同：

### 1. 上下文（短期记忆）

就是当前对话的 `messages` 列表。它有三个硬性限制：

- **窗口上限**：超过模型的上下文长度就直接报错，任务失败
- **成本**：每一轮都要把完整历史重新发一遍，成本随轮次增长
- **注意力稀释**：上下文很长时，模型对中间内容的关注度会下降，
  答案质量悄悄变差，而且不会报错

第三点最隐蔽。把几十篇文档全文塞进去，模型可能只认真看了开头和结尾。

### 2. 外部存储（长期记忆）

向量库、关键词索引、数据库。特点是**不进上下文，用时才检索**。

检索回来的内容才占用 token，这是它相对"全塞进去"的核心优势。

### 3. 结构化状态（工作记忆）

任务进度、已确认的事实、中间结果。通常存成一个 JSON 或数据类，
每轮按需注入上下文，而不是把所有历史都留着。

## 上下文管理的常见手段

- **截断**：只保留最近 N 轮，简单但会丢信息
- **摘要压缩**：把早期对话总结成一段话，损失可控
- **检索替代**：把长文档放外部，用工具按需查
- **结构化提取**：把关键结论抽成字段，丢掉原始对话

选择哪种取决于"丢了会怎样"。丢失工具调用记录会导致模型重复劳动，
丢失早期结论会导致前后矛盾。

## 一个实用原则

**上下文里只放"下一步决策需要的信息"，而不是"所有相关信息"。**

这条原则决定了工具该返回什么：搜索工具返回摘要而不是全文，
需要细节时让模型再调一次读取工具。这就是渐进式披露。
