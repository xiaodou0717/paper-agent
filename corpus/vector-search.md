# 向量检索

## 一句话定位

用"意思像不像"来找，而不是"字面有没有"。

## 为什么关键词检索不够

用户问"模型记不住之前说的话怎么办"，
文档里写的是"上下文窗口溢出导致的遗忘"。

关键词匹配：`模型` ✓、`记不住` ✗、`之前说的话` ✗ —— 匹配度很低。
语义检索：这两句话的向量距离很近 —— 能召回。

**关键词检索找"词"，向量检索找"意思"。**

## 基本流程

```
① 离线：文档 → 切块 → 每块算 embedding → 存向量库
② 在线：问题 → 算 embedding → 在库里找最近的 K 个块
```

两个环节都依赖同一个 embedding 模型，**换模型必须重建索引**。

## 相似度怎么算

最常用余弦相似度：两个向量的夹角余弦，范围 -1 到 1，越接近 1 越像。

实际系统里通常还会做**混合检索**：
向量召回 20 条 + 关键词召回 20 条 → 合并去重 → 重排序（rerank）→ 取前 5 条。

原因是两种方法各有短板：

| | 关键词 | 向量 |
|---|---|---|
| 专有名词、编号 | ✅ 精确 | ❌ 可能召回不相关 |
| 同义改写 | ❌ 漏 | ✅ 命中 |
| 可解释性 | ✅ 能说清为什么 | ❌ 只能给分数 |

## 常见误区

**只看相似度，不看元数据**

相似度 0.95 的块可能来自一篇过时的文档。
真实系统要加过滤条件（时间、来源、权限），而不是纯粹按分数排序。

**切块太小或太大**

太小：一句话一块，丢了上下文，embedding 质量差。
太大：一块 3000 字，包含五个主题，embedding 变成一个"平均"，什么都像什么都不像。

常见做法是 300-500 字一块，块间留 10%-20% 重叠。

**以为向量检索能替代关键词**

它不能。尤其在专有名词、错误码、人名这些场景上，
关键词检索的精确性无可替代。**混合检索才是主流。**
