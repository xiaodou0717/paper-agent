# Python 异步基础

## 一句话定位

异步不是"更快"，是"**等的时候别闲着**"。

## 事件循环

一个线程里跑一个循环，循环里排着很多任务。
某个任务遇到 `await`（等网络、等文件），就主动让出，循环去跑下一个。

**关键：只有 await 的地方才会让出。** 中间那段同步代码从头到尾占着。

## 协程 vs 线程

| | 协程（async/await） | 线程 |
|---|---|---|
| 切换成本 | 极低（用户态） | 较高（内核态） |
| 谁决定切换 | 代码里写 `await` | 操作系统抢占 |
| 适合 | IO 密集 | CPU 密集 |
| 共享变量 | 单线程，无竞态 | 需要锁 |

Agent 场景几乎全是 IO 密集（等模型 API、等工具），所以协程是正确选择。

## 三个必踩的坑

**坑一：在协程里调同步阻塞函数**

```python
async def handler():
    time.sleep(5)          # ❌ 整个事件循环停摆 5 秒
    await asyncio.sleep(5) # ✅ 只是这个任务等 5 秒
```

修法：`await asyncio.to_thread(blocking_func, args)`。

**坑二：以为 `gather` 一定并发**

```python
results = await asyncio.gather(*[call(i) for i in range(10)])
```

只有当 `call()` 内部真的 `await` 了 IO，才会并发。
如果它是纯计算，这十次还是串行跑的。

**坑三：忘记处理异常**

`gather` 默认在第一个异常时抛出，其余任务继续跑但结果丢了。
用 `return_exceptions=True` 拿到全部结果，再逐个判断。

## 一个判断标准

**这段代码执行的时候，CPU 在干活还是在等？**

- 在等（网络、磁盘、数据库）→ 用 async
- 在干活（循环、计算、解析大文件）→ 同步就行，或者丢线程池

搞混了会写出"看起来是异步，实际上更慢"的代码。
